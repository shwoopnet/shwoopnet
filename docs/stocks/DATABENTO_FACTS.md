# Databento facts read from public docs, Nov 12, 2026 (free reads, no data pulled)

1. Re-download of a purchased batch (databento.com/docs/api-reference-historical/batch/batch-submit-job, read Nov 12): "When you make a batch download request, you are only billed once for the request and, subsequently, you can download the data from the Download center multiple times over 30 days for no additional charge." Download center page: "Files expire 30 days after a download request has been submitted." Streaming (timeseries.get_range) is billed per outbound byte and "Duplicate streaming requests will incur repeated charges." A streaming connection cut for over 5 seconds stops billing for the rest.
   Consequence: use the BATCH route (batch.submit_job, delivery=download) for pulls (d) and (e), so a lost container does not force a second charge; fetch within 30 days. Batch is a different API route from the refused streaming call, so it needs its own allowance; nothing has been attempted.
2. Statistics schema (predecessor, public page): stat_type 1 "Opening price: the price of the first trade of an instrument", stat_type 11 "Close price: the last trade price and quantity during a trading session". These are FIRST and LAST trade, not proven to be the official auction prints. Pilot assertion to run first once pulls are allowed: SPY on 2026-08-27, CLAUDE.md measured official close print 771.10 (size 1,096,888). If stat 11 differs, the official print must come from the `trades` schema by auction condition (bigger pull, estimate first), and the cards' price definition stays UNPROVEN until then.
