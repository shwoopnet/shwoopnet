## 0. Arithmetic note (flagged, not silently fixed)
The registration says "14 features = 1,512 cells" and "15 features = 1,728 cells". 14 x 3 x 2 x 3 x 3 x 4 = 3,024, and 15 features = 3,240 cells. 1,512 and 1,728 are exactly half of that, so the registered cell count is an arithmetic slip. I score the FULL grid of the 15 features below (3,240 cells), every cell counted. N tried for deflation = V2 5,319 + Refinement about 900 + 3,240 = 9,459 (Bonferroni two-sided 0.05 z about 4.56). Also stated beside it: the registered N about 7,947 (z about 4.5) and the README bar 5.0 to 5.3 (GEN1 ledgers N 211,074 and 800,780).

## 1. Universe and price basis
[live figure removed, ask Main] One row = (asset, window close c, look L in {180, 360, 600} seconds left). Main rows (candle basis): Kalshi 1 minute candles in scratch oi/*.jsonl (btc, eth, xrp, gold), plus w_oieth3/eth_ext.jsonl and w_oieth3/seed.jsonl (ETH), w_golddecay/ext2_gold.jsonl (gold), deduped by ticker, preferring a row with a result. Each window has 12 candles ending c-660 ... c. The look candle is the one ending at c-L. YES ask = ac, NO ask = 1 - bc, both from that candle's close. Valid row: both prices parse, 0 < ac <= 1, 0 <= bc < 1, 0 <= ac - bc <= 0.10 (a stale or crossed candle is not a price anyone could buy at; the exclusion count is reported). Result: stored result; where missing (ETH, 495 windows) inferred from the settlement candle (end c): bc >= 0.98 means YES, ac <= 0.02 means NO, else the window is dropped. Inferred rows are flagged. R6 rows (book basis, only for the two R6 features): R6 book15r6 in scratch w_spotlead/r6/book15r6 (Oct 29 to Nov 11), asks from the last book row with t_recv <= close - L: YES ask = 1 - no_bid_px_1, NO ask = 1 - yes_bid_px_1; result from coverage.csv.gz; a window needs a row within 5 s before the look and a result. [live figure removed, ask Main] One contract per window per cell. PF = gross wins / gross losses per contract.

## 2. Spot data and definitions
Spot: Coinbase Exchange 1 minute candles (keyless): BTC-USD (w_spot/cache), ETH-USD and XRP-USD (w_sweep/cb, pulled), PAXG-USD (w_spotgold/cache) for gold. [live figure removed, ask Main] Features, all computed with data at or before the look only. "Signed" = positive favours YES. 1-4. ret3, ret5, ret10, ret15: ln(S(look)/S(look - h)), h = 3, 5, 10, 15 min, own asset. Signed.
5. zdist: ln(S(look)/ref) / (sigma(look) * sqrt(L/60)). Signed.
6. rvpct: percentile rank of sigma(look) among the same asset's sigma at the same look in the previous 288 windows (needs at least 96 priors). Unsigned.
7. div: [yes mid at look - yes mid at look+s0] minus [Phi(z at look) - Phi(z at look+s0)], s0 = min(L+180, 660) seconds left, yes mid = (ac+bc)/2, z at look+s0 uses sigma(look) and sqrt(s0/60) and S at that time. Signed (positive: Kalshi rose more than spot justified).
8-10. xoi3, xoi6, xoi9: the OTHER asset's open interest relative change (oi(look) - oi(start))/oi(start), start = max(look+h, c-660) i.e. horizon h = 3, 6, 9 minutes clipped to the data start of the window (so at look 600 all three are the 1 minute change; at look 180 the 9 minute horizon is 8 minutes). Other asset: Bitcoin takes ETH OI, ETH takes BTC OI, XRP takes BTC OI, gold has none (NA, cells empty but counted). Unsigned. 11-12. gb5, gb10: lead asset's spot log return over 5 and 10 minutes at the look. Lead asset = PAXG for Bitcoin, Ethereum and XRP; BTC-USD for gold. Signed.
13. [live figure removed, ask Main] (L-40 is V2's sqrt(8) generalised: 120 s gives 8.) Rows: Bitcoin, Ethereum, XRP windows with spot and strike (Oct 22 to Nov 9); price from the candle basis. Gold NA. Signed.
14. tsr: touch size imbalance = (yes_bid_sz_1 - no_bid_sz_1)/(yes_bid_sz_1 + no_bid_sz_1) from the R6 row at the look (YES bid size is demand for YES, NO bid size is demand for NO). R6 rows. Signed.
15. lti: large trade taker imbalance. [live figure removed, ask Main] R6 rows. Signed.

## 3. Cells (3,240)
feature (15) x tercile (top, bottom, middle) x direction (follow, fade) x look (180, 360, 600) x band (0.10 to 0.30, 0.30 to 0.60, 0.60 to 0.87 of the bought side's ask; lower edge inclusive, 0.87 inclusive) x asset (4). Tercile: for a signed feature x = |v|, for an unsigned feature x = v. Cut points q33 and q67 = the 33.33rd and 66.67th percentile of x over the TRAIN rows of that (feature, asset, look), nothing else. top: x >= q67; bottom: x <= q33 and not top; middle: otherwise. Fewer than 30 train rows = no cuts, cell empty. Side: signed feature: s = YES if v > 0, NO if v < 0 (v = 0 skipped). Unsigned feature (rvpct, xoi): s = the side whose Kalshi mid rose over [look+s0, look] (same s0 as div), skipped if unchanged. follow buys s, fade buys the other side. The bought side's ask must lie in the band. Splits: per (feature, asset), the distinct UTC close dates of its rows (any look) sorted, first third (index < floor(D/3)) = TRAIN, next third = VALIDATE, last third = HELD-OUT. The R6 features, and cfrti, exist only for part of the range, so their thirds are cut within the days they exist (stated so that the first third is not empty). Held-out rows are excluded from every number computed by score.py; frozen cells are scored on them only by heldout.py, by the session lead.

## 4. Scoring (train and validate only)
[live figure removed, ask Main] Day-clustered bootstrap (resample days with replacement, 5,000 draws, seed 1) 90 percent interval of mean cents per contract at +1c, computed where n >= 30. Day-clustered z = mean / cluster standard error (sum over days of (day total - mean x day n)^2)^(1/2) / n. Counted: cells with validation n >= 60; cells with validation cluster z >= 2 at +1c (naive), and the same at the deflated bar 4.56 (also 4.5 and 5.0 to 5.3); pooled train+validation z also given. Every cell goes into cells.csv, none dropped. Shortlist rule (registration): train n >= 60 and validate n >= 60, cash PF at +1c >= 1.3 in both, validation bootstrap lower bound > 0; at most 3 advance, ranked by validation lower bound. Not clearing the deflated bar = exploratory, never a pass. No look at the held-out. frozen.json plus heldout.py (not run) for the session lead, and for shortlisted cells the correlation of daily shadow P/L (cell rule, +0c, per contract cents summed per CT day, train+validate days) with gold L1 daily cash P/L from dash_report.json (cash recomputed from avgFill and avgFee, exits at settledPnl) when 10 or more overlap days. Extra independent check (Jun to Jul Bitcoin file) only if a Bitcoin cell is shortlisted and its feature can be computed there; not run otherwise.
