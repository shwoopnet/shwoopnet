# W-OIGAP1 registration (written before any scoring; diagnostic only, try count 0, no rule proposed, nothing promoted)
Question: candle model PF is 1.70 pooled Sep 2 to Nov 9 (514 triggers, +0c slip) but live OICORE cash PF is about 1.3. Where does the gap come from.
Data: live = w_oigap/rep.json (nightly report, generatedAt 2026-11-10T18:59Z, slotOrders strategy OICORE; 97 rows, filled and no fill, since 2026-10-30). Model = oi/btc.jsonl plus fwd_cache.jsonl (fwd fills rows missing/not ok in main), KXBTC15M windows, settled result only. skips = report.skips.rows (last 7 days only, reason counts).
Model trade (oicore_hist.py trade / score41.py): OI(c-180) minus OI(c-360) >= 86300; cheaper side = YES if ask(c-180) in 0.05..0.50 else NO if 1-bid(c-180) in 0.05..0.50; fill at that side's ask at candle ending c-120 (must be 0<p<1); hold to settlement. Pooled set must reproduce n 514 / PF 1.70 at +0c (check first; if not, report the difference).
Basis: cash per contract, win = 1-paid-fee, loss = -paid-fee. Model fee = 0.07*p*(1-p). Live paid = avgFill (YES) or 1-avgFill (NO), live fee = avgFee per contract, win/loss recomputed from ticker result vs side (not stored settledPnl). PF = gross wins / gross losses. Per contract unless labelled dollar (weighted by filled count).
Periods: PRE = model triggers closing before 2026-10-30T12:00Z; LIVE = closing from that time to the last settled window in the cache; also halves of LIVE by median live order time. Live fills only in LIVE.
Waterfall (attribution rule, fixed order, each step changes ONE thing; effect = PF after minus PF before, plus net c/ct; order dependence is stated and each step is also reported in isolation vs the pooled start):
  W0 model pooled (all 514).
  W1 model restricted to LIVE period (period effect: PRE vs LIVE regime).
  W2 LIVE model triggers restricted to windows where live has a filled order (coverage / skipped triggers; list skipped ones with reason from live no-fill rows, skips rows where present, else unknown).
  W3 same windows, entry price replaced by live paid (slippage: look-candle c-120 ask vs fill).
  W4 same, fee replaced by live avgFee.
  W5 add live fills with no model trigger on the ticker (side/price/band mismatch: live looked at a different second than the candle).
  W6 weight each trade by live filled contracts (dollar PF; size mix: 5 then 10 then 12 contracts, cheap high-variance wins carry more or fewer dollars).
  Endpoint W6 must equal live cash dollar PF recomputed from avgFill and avgFee.
Also report (descriptive): (a) slippage mean/median in cents, live paid minus c-180 ask and minus c-120 ask, by side; (b) win rate model LIVE vs live fills and matched only, with 90 percent Wilson or bootstrap interval; (c) fill coverage counts: model triggers in LIVE, filled, no fill rows (status), no order at all with skip reason counts where the 7 day skips cover them; (d) price band mix (0.05-0.10, 0.10-0.20, 0.20-0.35, 0.35-0.50) and contracts per order (model vs live), cheap-vs-dear PF; (e) triggers per CT day / per window and live fills per day; (f) fee share: sum fee / gross win and fee / |net| for model and live (net of fee vs gross of fee PF).
Bootstrap: 90 percent interval on each PF by whole-trade resampling, 5000 draws, seed 1. With under about 100 live fills no step can be separated from noise unless its interval excludes the neighbour; say so.
Biggest contributor rule: largest absolute PF step among W1 to W6 in the fixed order AND in isolation; if they disagree, say so.
Caveats registered now: the model entry fills at the c-120 ask while live orders go at about c-160 to c-177 (so slippage mixes time and spread); live-only fills W5 are selection by the live trigger reading a different candle; PF is ratio of sums and not additive; order effects.

## Results (scored after registration; an.py, an.out)
Reproduction: btc.jsonl-only pooled n 514, PF 1.70 (+1c 1.54); with 8 newer windows from fwd_cache n 522 PF 1.69 (used as W0). Live cash (avgFill/avgFee, result from market): 81 fills, 14 wins, dollar PF 1.30, +$26.15 (stored settledPnl PF 1.11, +$11.00; pre-741 rows booked differently); per contract PF 1.36.
Waterfall PF (per contract unless stated): W0 1.69 -> W1 model in live period (92 triggers, 18 wins) 1.21 [0.66,1.99] -> W2 only windows live filled (64) 1.06 -> W3 live paid price 1.21 -> W4 live avgFee 1.36 (isolated fee effect -0.01; the +0.15 step is one matched window where live bought the other side and won) -> W5 add 17 live-only fills 1.36 -> W6 weight by contracts 1.30 (= live dollar PF).
Steps in PF: period -0.48, coverage -0.15, price (live paid below c-120 ask, mean -2.4c, vs c-180 ask -1.5c) +0.15, fee/side-mismatch +0.15, live-only 0.00, size weighting -0.06. Sum -0.39 = 1.69 -> 1.30.
Biggest: period (the same candle rule on Oct 30 to Nov 10 windows is 1.21 vs 1.80 before Oct 30; PRE minus LIVE 0.60, 90 percent [-0.26, +1.28], P(diff<=0) 0.12). Live execution beat the model, not lost to it. Live win rate 17.3 percent (14/81) vs model PRE 26.7 percent. Second half of live fills PF 0.61, model on the same windows 0.57.
Coverage: 28 model triggers had no live fill (15 have a no-fill row, 13 no row; of those 13 the 7 day skips explain 6: cheap_skipped 5, cap 1); the 28 were 6 wins, PF 1.53. 17 live fills had no candle trigger (mostly 0.03 to 0.06 prices at c-180 under the band; live saw a different second). Fee share: fees 16 to 18 percent of gross-of-fee net live vs 10 percent model pooled; fee formula matches avgFee within 0.0001.
