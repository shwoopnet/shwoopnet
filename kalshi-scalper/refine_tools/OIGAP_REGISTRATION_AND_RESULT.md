# W-OIGAP1 registration (written before any scoring; diagnostic only, try count 0, no rule proposed, nothing promoted)
Question: the candle model PF (pooled Sep 2 to Nov 9, +0c slip) is higher than live OICORE cash PF. Where does the gap come from. Data: live = w_oigap/rep.json (nightly report, slotOrders strategy OICORE, filled and no fill, since 2026-10-30). Model = oi/btc.jsonl plus fwd_cache.jsonl (fwd fills rows missing/not ok in main), KXBTC15M windows, settled result only. skips = report.skips.rows (last 7 days only, reason counts). Model trade (oicore_hist.py trade / score41.py): OI(c-180) minus OI(c-360) >= 86300; cheaper side = YES if ask(c-180) in 0.05..0.50 else NO if 1-bid(c-180) in 0.05..0.50; fill at that side's ask at candle ending c-120 (must be 0<p<1); hold to settlement. Pooled set must reproduce n 514 / PF 1.70 at +0c (check first; if not, report the difference).
Basis: cash per contract, win = 1-paid-fee, loss = -paid-fee. Model fee = 0.07*p*(1-p). Live paid = avgFill (YES) or 1-avgFill (NO), live fee = avgFee per contract, win/loss recomputed from ticker result vs side (not stored settledPnl). PF = gross wins / gross losses. Per contract unless labelled dollar (weighted by filled count). Periods: PRE = model triggers closing before 2026-10-30T12:00Z; LIVE = closing from that time to the last settled window in the cache; also halves of LIVE by median live order time. Live fills only in LIVE. Waterfall (attribution rule, fixed order, each step changes ONE thing; effect = PF after minus PF before, plus net c/ct; order dependence is stated and each step is also reported in isolation vs the pooled start):
  W0 model pooled (all 514).
  W1 model restricted to LIVE period (period effect: PRE vs LIVE regime).
  W2 LIVE model triggers restricted to windows where live has a filled order (coverage / skipped triggers; list skipped ones with reason from live no-fill rows, skips rows where present, else unknown).
  W3 same windows, entry price replaced by live paid (slippage: look-candle c-120 ask vs fill).
  W4 same, fee replaced by live avgFee.
  W5 add live fills with no model trigger on the ticker (side/price/band mismatch: live looked at a different second than the candle).
  W6 weight each trade by live filled contracts (dollar PF; size mix: cheap high-variance wins carry more or fewer dollars).
  Endpoint W6 must equal live cash dollar PF recomputed from avgFill and avgFee. Also report (descriptive): (a) slippage mean/median in cents, live paid minus c-180 ask and minus c-120 ask, by side; (b) win rate model LIVE vs live fills and matched only, with 90 percent Wilson or bootstrap interval; (c) fill coverage counts: model triggers in LIVE, filled, no fill rows (status), no order at all with skip reason counts where the 7 day skips cover them; (d) price band mix (0.05-0.10, 0.10-0.20, 0.20-0.35, 0.35-0.50) and contracts per order (model vs live), cheap-vs-dear PF; (e) triggers per CT day / per window and live fills per day; (f) fee share: sum fee / gross win and fee / |net| for model and live (net of fee vs gross of fee PF). Bootstrap: 90 percent interval on each PF by whole-trade resampling, 5000 draws, seed 1. With under about 100 live fills no step can be separated from noise unless its interval excludes the neighbour; say so.
Biggest contributor rule: largest absolute PF step among W1 to W6 in the fixed order AND in isolation; if they disagree, say so. Caveats registered now: the model entry fills at the c-120 ask while live orders go at about c-160 to c-177 (so slippage mixes time and spread); live-only fills W5 are selection by the live trigger reading a different candle; PF is ratio of sums and not additive; order effects.
