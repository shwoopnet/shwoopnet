# LADBFLY1 and XSER1 (registered Nov 11, 2026, before any count is made; research only, no live change, no API call)
Data: `quote-data` branch, `book/<date>/<hhmm>/{book,trades}.csv.gz` (KXBTCD, 7 strikes nearest the money, top 5 YES and NO bids, sizes, every 3 s, Oct 29 on) and `quotes/<date>/<hhmm>/{quotes,results}.csv.gz` (15 minute quotes with strike, last 150 s per window, Oct 22 on). Script `src/scalper/ladbfly1.py`. N tried: 2 (report bars at N 8,795, z about 4.39, and N 1.1M, z about 5.34). Verdicts: zero violations after fees = CLOSED; any exploitable count = LEAD with n, size and cash P&L per violation, no strategy claim without a held-out.

## Common rules
- Per strike: YES bid = yes_bid_px_1, size yes_bid_sz_1; YES ask = 1 - no_bid_px_1, size no_bid_sz_1. Rows with a missing top level are skipped.
- A snapshot = rows of one event whose poll_ts_local_ms are within 2 s of the first row of the cluster (new cluster after a gap of 1.5 s). Pairs and triples use only strikes inside one snapshot.
- Taker fee 0.07 p (1-p) per contract per leg at that leg's price, unrounded; a leg sold at YES bid b or bought as NO costs the same p(1-p). Net = book credit minus all leg fees. "Survives fees" = net > 0. Size = minimum top-of-book size across the legs. An episode = consecutive snapshots in which the same strike set violates (a gap breaks it); counts are given in snapshots and episodes, per day.
- Settlement outcome of a strike (for cash P&L) is inferred from the event's last snapshot: yes if YES bid >= 0.95, no if YES ask <= 0.05, else unknown (left out of cash P&L, counted).

## LADBFLY1
(a) Monotonicity, every ordered pair of recorded strikes K_i < K_j: violation if ask_i < bid_j. Trade: buy YES K_i at ask, sell YES K_j at bid (buy NO). Payoff at settlement is >= 0 (YES_i pays whenever YES_j does), so the locked minimum is bid_j - ask_i - fees; cash P&L adds 1 if the settlement falls between the strikes (inferred outcomes) and is reported beside the minimum.
(b) Butterfly as on the card, every triple of ADJACENT recorded strikes K1<K2<K3: price(K1) - 2 price(K2) + price(K3) < 0 with executable fills: buy K1 at ask, sell K2 twice at bid, buy K3 at ask, credit 2 bid2 - ask1 - ask3 minus 4 legs' fees. NOTE stated before counting: a digital butterfly is NOT a lock (payoff 1[S>K1] - 2*1[S>K2] + 1[S>K3] is -1 for S between K2 and K3); only (a) is an arbitrage. (b) is counted and its settled cash P&L is reported (outcome from inferred settlement) to show whether it is anything but a bet.
(c) Sanity: a strike whose yes_bid + no_bid >= 1 (crossed book), counted.

## XSER1
Windows: KXBTC15M windows whose close_time (results.csv) is on the hour (xx:00 UTC), with a KXBTCD event of the same close_time in the book data. K15 = the strike column of the 15 minute quotes in that window. Ladder strike K = the recorded strike nearest K15 (ties: lower). Pair each 15 minute quote with the nearest-in-time ladder snapshot (t_recv_ms vs poll_ts_local_ms, both local clock; within 3 s). If K <= K15 the ladder YES should be >= the 15 minute YES; if K > K15 it should be <=. Violation (K <= K15): ask_ladder(K) < yes_bid_15m; trade buy ladder YES at ask, sell 15m YES at bid. Violation (K > K15): yes_ask_15m < bid_ladder(K); trade the other way. Taker fees both legs, as above. Primary count: the last paired sample at least 5 s before the close; secondary: all paired samples in the last 150 s. Also reported: the mid-price gap (ladder mid - 15m mid) by distance |K - K15|, because K is not K15 and the gap in the strike carries real probability.
Contract terms: Kalshi's hourly KXBTCD and 15 minute KXBTC15M are both written on the CF Benchmarks Bitcoin Real-Time Index; whether both use the same averaging window at the same instant is NOT verified here (no terms read, no API call), so any violation is flagged "same-index unverified".
