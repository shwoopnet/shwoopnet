Purpose (the owner): income. Whether it is a version does not matter for this table. It is counted in m. No promotion language.

## Rule (OICORE as written in kalshi-scalper/README.md#SLOT-OICORE, applied per market)
- Window: a 15 minute market. OI rise r = (open interest of the candle ending exactly 180 s before the close) minus (open interest of the candle ending exactly 360 s before the close). Either candle or either OI value missing: no signal, counted.
- Signal fires when r >= C, where C is that market's own constant, FIXED NOW as a rule and computed from the SEARCH half only: the 90th percentile of r over that market's SEARCH-half windows with a computable r (sorted ascending, index ceil(0.9 n) - 1; the SEARCH half is engine1_split's per-market constant, the same dates ENGINE1 used). If that C is not above 0 the market is reported "no usable threshold". BTC's live constant 86,300 is reported once as a reference line (BTC_LIVE) beside BTC's own C.
- Side: the cheaper side by ask (yes if yes ask <= no ask). Band: its ask from 0.08 to 0.50 inclusive. Entry: the FIRST candle whose end is from 180 s to 120 s before the close (both inclusive) with a sellable quote (0 < bid < ask < 1) and its cheap side's ask inside the band; none: no entry (counted). Hold to settlement (so the no-mark flaw does not apply).
- Cost: cash, per order at 10 contracts, fee ceil(round(0.07 n p (1-p) x 100, 9))/100 on the entry (settlement has no exit fee); entry price min(ask + h, 0.99) with h = 0.01 (primary) and 0.02. Scored by engine1_core.score with exit "H" (the same code ENGINE1 used).
- Per market and per phase (SEARCH, VALIDATE, and HELD-OUT as a separate read): n, wins, PF at 1c and at 2c, net cents a contract at each, signals a day (n over the phase's calendar days from first to last close), and the day-by-day correlation of the net dollars of that day with BTC's OICORE net dollars of the same day (Pearson over days where both traded, at least 10 common days or "na").
- Phases: SEARCH and VALIDATE from the archive (closes before 2026-10-03T16:00Z, ENGINE1's split constants) and the HELD-OUT read from the ENGINE1 held-out pull (closes from 2026-10-03T16:00Z to 2026-10-28 for the A series, to 2026-11-03T16:00Z for the B series), LABELLED "read before by ENGINE1" (the data is not fresh; C comes from SEARCH only and nothing is tuned after).
- Markets: BTC (reference), ETH, SOL, XRP, HYPE, BNB, NEAR, ZEC, gold, then the non-crypto 15 minute series the data holds (WTI, SILVER, COPPER, NATGAS, EURUSD, GBPUSD, USDJPY, PALLADIUM, PLATINUM, and the index series if the archive or the NC15 extract carries it). DOGE is on the Head's list; it is on the declined list (7e) and Dogecoin was removed from the bot, so it is run ONLY if the Head confirms in one line. Series with no OI in the candles are reported as such.
- m: one try per market (about 20 settings); added to the ledger as such.
- Honest labels: SEARCH and VALIDATE are history; the held-out is a second look at data ENGINE1 already read; the only fresh evidence is forward. Quotes are candle quotes (upper bound; a live fill is worse).

## Hand case (invented, 3 windows, one market)
close = 10000. SEARCH windows: A: oi(close-360)=100, oi(close-180)=120, r=20; B: r=0; C: r=5 (all computable). Sorted r: 0, 5, 20; n = 3, index ceil(2.7) - 1 = 2, so C = 20. A fires (r = 20 >= C). Entry candle at end 9830 (170 s before close, in 180..120): yes bid 0.20, yes ask 0.24, so no ask = 1 - 0.20 = 0.80; cheap side yes, ask 0.24 in 0.08..0.50: entry yes at 0.24. At h = 0.01 paid 0.25; fee at 10 contracts = ceil(round(0.07 x 10 x 0.25 x 0.75 x 100, 9)) / 100 = ceil(13.125) / 100 = 0.14. If the market settles yes: net = 10 - 2.50 - 0.14 = 7.36; if no: -2.50 - 0.14 = -2.64. PF over {7.36, -2.64} = 7.36 / 2.64 = 2.788; cents a contract = (7.36 - 2.64) / 20 x 100 = 23.6. The fixture test reproduces these.
