# 60-day tape, 1 minute bar builder, blind second build: readings list T1 to T18 (Testing Desk, Nov 17, 2026)

Not opened: Desk A's builder, tests, any tape sample. Each reading is what I do unless Desk A settles it in the file.
T1 Time parse: created_time is ISO 8601 UTC, ending Z (or +00:00), with or without a fraction of 1 to 9 digits; I parse it to an exact integer number of nanoseconds (no floats); a different form raises.
T2 Bar: end_ts = (floor(t_ns / 60e9) + 1) x 60 epoch seconds, so a trade exactly on a minute boundary belongs to the NEXT bar (12:01:00.000 -> bar ending 12:02:00; 12:00:59.999999999 -> bar ending 12:01:00).
T3 Order inside a bar for open and close: by (time as an exact integer, then trade_id compared as a string); the file's own order is not trusted. (Your stored order is by the ISO STRING, which can differ from true time order when fractions have different lengths, e.g. 12:00:01Z sorts after 12:00:01.5Z as a string; I read the rule as true time, tie by trade_id; please confirm.)
T4 Duplicates: a row repeated for the same (ticker, trade_id) is kept once, the FIRST in file order (and, over several files, in sorted path order); a repeat whose other fields differ is counted (duplicate_differs) and the first is kept.
T5 Prices are decimal strings: I use exact decimals (no float) for open, high, low, close comparison and print the value as a float of the exact decimal; a price that is not a positive decimal raises.
T6 Block trades (is_block_trade): true or false (case-insensitive); anything else raises. Block rows are excluded from open, high, low, close, volume, n_trades, buy_volume and sell_volume; they add count to block_volume and 1 to block_count of their bar.
T7 A bar that has ONLY block trades has no open, high, low, close: no bar row is written for it; its block volume and count go to a separate per-ticker-file summary line (bars_only_block, block_volume_in_those). A bar with at least one non-block trade is written with its block columns.
T8 volume = sum of count of non-block trades; n_trades = their number; a trade with count 0 counts in n_trades and can be open or close but adds 0 volume; a negative or non-integer count raises.
T9 taker_side is buy or sell (case-sensitive as the API gives); buy_volume and sell_volume are sums of count by side; a non-block trade with any other taker_side counts in volume and n_trades but in neither side column, and is counted in unknown_side_trades.
T10 Empty minutes: no row; nothing is carried forward.
T11 One output row per (ticker, end_ts) with columns ticker, end_ts (integer), open, high, low, close, volume, n_trades, buy_volume, sell_volume, block_volume, block_count, sorted by (ticker, end_ts); floats printed with 17 significant digits; all prices from the exact decimals.
T12 A minute never straddles two UTC dates, so each (ticker, date) file builds independently; if two files hold the same ticker and date, I merge them with the dedupe of T4 and note it.
T13 The wall: the builder reads only the tickers given to it (the 14 PERPSCALP2 names and the 13 basket names, or all if you say so), the ticker column FIRST, before any other column; rows of other tickers are counted and not parsed. Please give the tape file path layout (for example tape/<date>/<ticker>.csv.gz or per ticker folders) and the exact ticker list.
T14 Tick per ticker per file: the smallest positive difference between the sorted distinct non-block trade prices of the file (exact decimals); printed in a summary line, not in the bar rows. Block prices are not used. Is that your reading of 'the smallest price step observed for the ticker in the same file'?
T15 Summary per (ticker, file): rows read, rows kept, duplicates dropped, duplicate_differs, block rows, unknown_side_trades, bars written, bars_only_block, tick; the puller's page log is not used.
T16 Columns are read by name; extra columns are ignored; a missing required column raises; header row required.
T17 Counts of trading days or session tests are not in the builder (UTC only); the lane code converts to ET, not the builder.
T18 Output hashes: one sha256 of the full bar file (rows sorted as T11, each line 'ticker,end_ts,open,high,low,close,volume,n_trades,buy_volume,sell_volume,block_volume,block_count' with the T11 float format) and the same for the summary lines, so Auditor B can compare file hashes as well as fields at 1e-9.
