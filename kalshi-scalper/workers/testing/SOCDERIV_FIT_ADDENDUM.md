## ADDENDUM 5 Nov 14 (the Head's final SOCDERIV spec, 07:10Z, after Auditor B's differential of the two fits; the box-edge text is the History Miner's, which the Head confirmed for both builds). Written BEFORE the code change.
1. **Boundary rule.** After the 2-D polish a rate is ON A BOUND if it is within 1e-12 of 0.01 or 6.0 AND the SSE gradient on it points out of the box (central difference with h = 1e-6; one-sided inward if h would leave the box; at the lower bound a gradient above zero points out, at the upper bound below zero). A rate on a bound is set EXACTLY to the bound and held; the other rate is polished alone by a 1-D Levenberg-Marquardt / Gauss-Newton step with the same stops (step under 1e-13, or the SSE improving by less than 1e-13 relative, a step never accepted if it raises the SSE or leaves the box). The cap of 200 is SHARED with the 2-D passes (the iteration count adds both), and cap_hit is true if the cap ended either stage. Both rates on bounds: nothing is iterated. The 1-D result is used only if its SSE is not above the 2-D result's SSE + 1e-15; otherwise the 2-D result stands. Each build prints `fits_on_bound`, the number of distinct fits that ended with a rate on a bound, in the "polish" block (the cap and iteration figures there are unchanged in meaning).
2. **Per-game CSV columns, final** (supersedes addendum 3's column list): game_key, fit_iters, cap_hit, rate_home, rate_away, sse, leg_ticker, leg_type, strike, model_value, market_mid, gap, side, edge, fires. `leg_type` is `btts` or `team_total` (NOT teamtotal). `gap` = model_value minus market_mid (the plain gap; the old cheaper-side gap is no longer in the gap column). `side` = `yes` or `no`, the cheaper side the aggregate trades (the side with the lower ask: YES if the YES ask is at most 1 minus the YES bid, a tie takes yes). `edge` = that side's model value minus its ask (model minus the YES ask for yes, the NO value 1 - model minus the NO ask 1 - bid for no): exactly the figure the aggregate's gap statistics use. `fires` is True when edge >= 0.08 and the spread <= 0.04 (the same as the aggregate). A blank row (a leg with no fit) has gap, side and edge blank like the other value columns, fires False.
## Hand cases (invented)
- On a bound at the lower edge: market values generated exactly from rates (0.5, 0.005) (below the box): the fit returns the second rate EXACTLY 0.01 and the first rate within 1e-8 of the 1-D minimiser of SSE(a, 0.01) found by an independent golden-section search; fits_on_bound counts 1 for that fit; the free-coordinate gradient is under 1e-9 (the old polish stopped with about 8e-7).
- On a bound at the upper edge: values generated from (6.8, 1.0): the first rate EXACTLY 6.0 and the second within 1e-8 of the independent 1-D minimiser of SSE(6.0, b).
- Both on bounds: values generated from (0.001, 0.002): both rates exactly 0.01 or the box edge they are pushed to, nothing iterated in the 1-D stage (iteration count equals the 2-D count), fits_on_bound counts 1.
- Interior optimum (any ordinary case, and (0.012, 1.4)): no bound is held, the result equals the 2-D polish and fits_on_bound is 0. A rate within 1e-12 of a bound whose gradient points INTO the box is not held.
- The 1-D stage result is discarded when its SSE exceeds the 2-D result's by more than 1e-15 (a unit test with a stub: the stage returns the 2-D result).
- Per-game file: the header is exactly the 15 names above in order; leg_type values are btts and team_total; on the fixture gap equals model_value minus market_mid recomputed from the written fields to 1e-12; edge equals the aggregate's own gap function of (model_value, bid, ask) recomputed from the candle values; side is yes when ask <= 1 - bid + 1e-9; fires equals (edge >= 0.08 - 1e-9 and spread <= 0.04); blank rows have gap, side, edge empty.

- CORRECTION to the two bound hand cases above (found when the test first ran; the code was right, my stated tolerances were not): the SSE is flat to within double precision (about 1e-18 at a value near 1.5e-3) over about 3e-8 in the free rate, so a position tolerance of 1e-8 and a gradient of 1e-9 cannot be asked of any fit. The cases assert: the free rate within 1e-7 of the independent golden-section minimiser, the fit's SSE not above the golden-section SSE + 1e-15, and the free-coordinate central-difference gradient under 1e-8 (the real value on the upper-edge case is 5e-10).
