# MECH_REGISTRY first draft (Desk B, Nov 17, 2026)
Files: `MECH_REGISTRY_DRAFT_B.json` (20 declined patterns, 176 test entries), `declined_patterns.json` (hand-written from docs/STRATEGY_LIFECYCLE.md 7e), `build_mech_registry_draft.py` and `assemble_mech_registry_draft.py` (how it was made; rerunnable).
Source of the test entries: the README of the research branch (origin/claude/epic-ptolemy-0amjd9, 9,229 lines; origin/main's README stops at the October records). Only HEADINGS and the first paragraph after a "Pre-registration: ID" heading were used; result paragraphs were never read, and no profit factor, count or result figure is stored.
What is in it: every test whose result heading carries FALSIFIED, NOT_ENOUGH_DATA or "none passed" in the forms "ID result (...)" and "Result: ID, ...": 176 entries (95 FALSIFIED, 72 NOT_ENOUGH_DATA, 9 MIXED where one heading reports both). The six fields come from keyword rules in the builder (the spec's enumerations); `inferred` lists the fields that matched a keyword and `confidence` is "auto" only when all six did: **42 auto, 134 review**. Every review entry needs a human to correct the fields; 72 entries have no pre-registration paragraph found and were inferred from the heading label alone (weak).
Known gaps, stated so nobody reads this as complete: (1) tests whose status is not in a heading (the older Verdicts table, S01 to S42, the idea ledger, status lines in paragraphs) are NOT in; (2) some ids are artefacts of the heading parser and should be dropped or fixed in review: FLAT (is FLAT-R), DEV, OKX, KXTORNADO, KXMLBHR, KXRAIN, P06, MECH1S, MECH2S; (3) a multi-id heading keeps only its first two ids; (4) the entry and exit fields default to "taker" and "hold to settle" when no keyword matched, which is often wrong for ladder, perp and maker tests; (5) the slow-family paper list and ledger entries from other branches' READMEs were not merged. Desk A owns the schema: field names here follow the spec's six words and may need renaming.
