# S3 settled-results pull job: hand case, written BEFORE the builder code

Why (the Head, Nov 15): the combo recorder's daily settled file stops when the recorder is switched off, so S3's fills whose close falls later have no result; the job asks the settled result of every S3 paper fill ticker directly, through kalshi-pull, so S3 can be scored whatever the owner decides about the recorder. It is not dispatched by me; Auditor B checks it, Main dispatches it.
Builder `build_s3_results_job.py <combo-data checkout> <template job> <out file>`: reads ONLY the quotes.csv.gz files (never a results file), takes the S3 paper fills of the development window (S3's own qualifies and fills, entries 2026-11-13 to before 2026-11-26) and writes a job: one request per batch of at most 100 fill tickers, GET /markets with params `tickers` (the comma list, tickers sorted) and `limit` 100; id r001, r002 ...; ticker_allowlist = all fill tickers sorted; series_allowlist = the distinct series prefixes (the part of the ticker before the first "-"); max_requests = number of requests + 12 (the runner counts repeats); pacing_seconds 5.0; registration kalshi-scalper/workers/S3_COMBO_HOUSE_SIDE_REGISTRATION.md; the allowed endpoint is /markets with params tickers, status and limit only. It refuses to write a job of more than 1,000 requests or with no fill, and checks before writing that every request ticker is in the allowlist.
Made-up fixture: the tree T120 of make_s3_fixture.py with the results file DELETED (quotes only). Expected: 120 paper fills, 120 tickers C001 to C120 (KXMVE-C001 ...), 2 requests: r001 holds KXMVE-C001 to KXMVE-C100 (100 tickers, sorted), r002 holds KXMVE-C101 to KXMVE-C120 (20 tickers); params limit 100; max_requests 14; series_allowlist ["KXMVE"]; pacing 5.0; ticker_allowlist of 120. The runner's check_job accepts the job. A tree with no qualifying fill: the builder refuses to write ("no fill"). A file named results.csv.gz in the tree is never opened (the test makes it unreadable garbage and the builder still runs).
