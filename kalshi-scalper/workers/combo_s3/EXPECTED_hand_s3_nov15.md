## Note on case 4's precision (written when the test was run)
The scorer prints the bootstrap 5th percentile to three decimals, so run_hand_cases_s3.py compares the independent implementation's value to the printed one within 5e-4, not 1e-12 as case 4 first said. The pinned procedure itself is exact; only the comparison with the printed text is at its precision.

## Case 7, cut leg lists (written Nov 15, 2026 BEFORE the code change; Auditor B's finding on line 9)
The recorder cuts a `leg_tickers` cell at 600 characters at a whole leg and ends it with `|...`. Rule to build: such a cell is an INCOMPLETE leg list; the trailing `...` is never a leg series; a combo whose list is incomplete is "legs incomplete": it is in the all-combos line only, never in the NO WEATHER LEG line, unless some snapshot stored a complete list for it (then the complete list is used). A weather leg shown in a cut list still makes the combo a weather combo (the leg exists).
Unit: leg_series("KXA-1:yes|KXB-2:no") = (["KXA","KXB"], complete); leg_series("KXA-1:yes|KXB-2:no|...") = (["KXA","KXB"], incomplete); leg_series("") = ([], unknown).
Tree LG (made up): one snapshot at 2026-11-13T12:00Z, four combos, NO ask 0.79, size 5, volume 3, 3 legs, distinct events, close 2026-11-14T10:00Z, all result no: A cells complete no weather ("KXA-1:yes|KXB-2:no"); B cut, no weather shown ("KXA-1:yes|KXB-2:no|..."); C cut, weather shown ("KXHIGHNY-1:yes|KXB-2:no|..."); D cut in this snapshot and complete in a second snapshot at 14:00Z (same ticker D, a new event name not needed: D appears in snapshot 2 with its complete list but is already filled, so it is not a second fill). Read 2026-11-30T12:00Z, dev.
Expected: paper fills 4 | due 4 | settled 4; legs line: "paper fills with leg tickers stored 4 | leg unknown 0 | with a weather leg 1"; incomplete count printed: "legs incomplete 2" (B and C); the leg series seen count has no "..." entry; the NO WEATHER LEG line prints "settled 2" (A and D); the all-combos line prints "settled 4".
