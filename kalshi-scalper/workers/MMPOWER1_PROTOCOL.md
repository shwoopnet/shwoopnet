# MMPOWER1 (registered Nov 11, 2026, before any bootstrap or power number is computed): power and sample size for the single held-out read of MMSIM1
Research only, no live change, no network call except git on this repo. Cash basis, one contract per side per strike, same simulator as MMSIM1 (`src/scalper/mmsim1.py`, `mmsim2.py` BASE, `mmhour1.py` cells). DEVELOPMENT EVENTS ONLY: the 171 events closing before 2026-11-07T15:00Z. The script loads only book files in directories dated 2026-11-07 or earlier and drops every event at or after the cutoff before simulating; it scores, prints and counts nothing from a held-out event. Held-out file counts below come from the git file LISTING only (names, never content).

## Questions
1. At maker coefficient 0 (the true fee on KXBTCD per COST1) and at 0.0175 x p(1-p) (conservative bound): development cash PF of per-event P&L with a day-clustered bootstrap 90% interval (resample the 10 UTC days with replacement, pool their events, PF; 10,000 draws). Then, for N = 100, 200, 300, 500 events: P(PF >= 1.3) and P(PF >= 1.5) on a fresh set of N events, drawn two ways: (D) day-clustered (draw days with replacement, take whole days until N events, truncate to N), headline; (I) iid events with replacement. 5,000 draws per N and scheme. Also run both from the demeaned development events (true mean 0) so the false-pass rate of the same rule is reported.
2. Daily P&L (UTC close date, base rule, both fee bounds): mean, sd, lag-1 autocorrelation. Correlation with gold L1 over n overlapping days: 90% interval for r by the Fisher transform at n = 20 and 30 for observed r = 0 and r = 0.3, the smallest n whose 90% upper bound is under 0.3 when the observed r is 0, and the calendar date the 20th overlapping day exists counting from the first recorded day 2026-10-29 (every day one event or more, gold's nightly report taken as covering every day).
3. Leads: (a) block 12 to 18 Central, (b) high touch depth (YES plus NO touch size at or above the development 2/3 quantile), (c) both together, as defined in `mmhour1.py`. Per-event cell P&L. Shrinkage for best-of-92 looks, three stated scenarios for the true mean: k = 1 (no shrink), k = 0.5, and k = k_sel = max(0, (z - zmax) / z) with z the cell's day-clustered z and zmax the expected maximum of 92 standard normals (simulated, 200,000 draws); true mean = base mean + k x (cell mean - base mean) where base is the all-event mean at the same fee bound, applied by shifting the development cell events by a constant. Power = P(held-out PF >= 1.5) on N events (scheme D, 5,000 draws) over a grid N = 25 to 2,000; report the smallest N with power >= 0.8, or "not reachable" if no N up to 2,000 reaches it. The rule is the observed-PF bar only, not a significance test.
4. Held-out accrual: events at 24 an hour-grid per day with the dev quotable share and dev recorder coverage (development events over the development time span in hourly closes), projected to counts closing before 2026-11-17 00:00Z, 11-24 00:00Z, 12-01 00:00Z and the date n reaches 300 (all events, and the 12 to 18 Central block at 6 of 24 events). The file listing is counted by directory only.
Seeds: numpy default_rng(20261111) once, spawned in the order questions 1, 3, 4's zmax, so a rerun reproduces every number. Script `src/scalper/mmpower1.py`, run with `python3 -I`.
Prediction before running: the development PF 90% interval is wide (roughly 0.8 to 2.2 at the bound), a fresh 300 events reads PF >= 1.3 well under 60% of the time at the bound, the daily correlation needs 30 or more days, and the leads cannot confirm PF >= 1.5 at 80% power with a few hundred events once shrunk for selection. Not a decision: when to read the held-out set is for the parent and the owner. N tried: 0 new strategy looks (power analysis only).

## Result (Nov 11, 2026; development events only, 171 events, 168 quotable, 10 UTC days; held-out NOT read; script `src/scalper/mmpower1.py`, seed 20261111)
Cash basis, one contract per side per strike. D = day-clustered draws, I = iid event draws.
**Q1.** Development PF (per-event P&L, sd 41.7c): maker 0 = 1.41, day-clustered 90% interval [1.09, 1.88]; maker 0.0175 (bound) = 1.28, interval [1.00, 1.72]. Probability a fresh set of N events reads the bar, resampling the development events as they are (the true PF then is about 1.28, so more events do NOT help PF >= 1.5, they pull it down to 1.28):

| N | bound 0.0175: P(PF>=1.3) D/I | P(PF>=1.5) D/I | fee 0: P(PF>=1.3) D/I | P(PF>=1.5) D/I |
|---|---|---|---|---|
| 100 | 0.52/0.48 | 0.28/0.29 | 0.68/0.62 | 0.43/0.41 |
| 200 | 0.50/0.47 | 0.17/0.22 | 0.72/0.66 | 0.36/0.39 |
| 300 | 0.49/0.48 | 0.11/0.17 | 0.77/0.70 | 0.34/0.35 |
| 500 | 0.47/0.47 | 0.05/0.10 | 0.81/0.75 | 0.27/0.30 |

False-pass rate if the true mean is 0 (demeaned events), PF >= 1.3: N 100 0.12, N 200 0.04, N 300 0.02, N 500 0.00 (D, bound); PF >= 1.5: 0.03, 0.00, 0.00, 0.00. So a read at N 300 or more is hard to pass by luck, but a rule with true PF 1.28 passes the 1.3 bar only about half the time at the bound.
**Q2.** Daily P&L (base rule): mean +$0.624/day at the bound (+$0.851 at fee 0), sd about $1.23 ($1.21), lag-1 autocorrelation +0.32 (+0.30), n = 10 days so that autocorrelation is itself within noise (events per day 5, 14, 11, 24, 22, 20, 21, 19, 19, 13: early days were partly recorded). Fisher 90% interval for r: n = 20 and observed r 0: [-0.38, +0.38]; observed 0.3: [-0.09, +0.61]. n = 30: [-0.31, +0.31]; [-0.01, +0.56]. The smallest n whose 90% upper bound sits under 0.3 at observed r 0 is 32; at observed r 0.15 it is 111. So 20 days cannot show r < 0.3 even if the true value is 0 (the bound is 0.38); it can only fail to reject, or reject r near 0.6 or more. 20th day from Oct 29 is 2026-11-17 (complete after 00:00Z on Nov 18), 30th is Nov 27, 32nd is Nov 29.
**Q3.** zmax(92) = 2.48. Cells at the bound: block 12 to 18 CT n 46, PF 2.59, +12.42c per event, day z 3.28, k_sel 0.25; high depth n 142, PF 2.11, +2.71c per event (below the base +3.71c per event because it holds a third of the quotes), day z 2.02, k_sel 0; both n 43, PF 6.78, +7.53c, z 3.20, k_sel 0.23. Held-out events needed for 80% power that observed PF >= 1.5 (scheme D, true mean = base mean + k x (cell mean - base mean) by constant shift):

| cell | k = 1 | k = 0.5 | k = k_sel | PF at k_sel true mean |
|---|---|---|---|---|
| block 12 to 18 CT (n 46) | 25 | 75 | NOT reachable (power 0.54 at 100, 0.57 at 300, 0.64 at 1,000) | 1.53 |
| high depth (n 142) | 150 | 75 | 50 | 2.69 |
| both (n 43) | 25 | 25 | 25 | 2.57 |

Fee 0 gives the same pattern with smaller N (block at k_sel: 75 events). Read this carefully: the selection shrinkage puts the block's true PF right at the bar (1.53), so 1.5 is a coin flip however many events arrive; and the cell PF is not comparable with the base PF because a cell holds fewer quotes per event. High depth reaches PF 1.5 easily because its P&L has a small spread, but its mean per event is below the base, so PF >= 1.5 there does not mean a better strategy. A PF bar alone is the wrong test for the leads; a held-out mean per event above zero with a day-clustered z is the better one (not registered here).
**Q4.** Development recorder coverage 0.78 of hourly closes (171 events over 220 hours; about 0.88 on the last six full days), quotable share 0.98. Held-out events (closing on or after 2026-11-07T15:00Z, from the listing: 6 directories a day, 5 on Nov 10, 4 so far on Nov 11): before Nov 17 00:00Z about 172 quotable at dev coverage (225 at full coverage); before Nov 24 about 300 (393); before Dec 1 about 428 (561). Note this is the held-out set only: the protocol's "about 400 events on Nov 17" counts the 168 development events too. n = 300 held-out quotable events arrives about 2026-11-20 (full coverage) to 2026-11-24 (dev coverage). The 12 to 18 Central block holds a quarter of them: 43 to 56 events by Nov 17, 75 to 98 by Nov 24, 107 to 140 by Dec 1; 300 in the block not before late December.
Reading for the parent and owner (not a decision): a Nov 17 read gives about 172 to 225 events, short of the registered n >= 300 bar, with day-clustered z judged on only 10 held-out days; it can falsify (a PF under 1) but its chance to confirm a true PF 1.28 at PF >= 1.3 is about 0.5 and at PF >= 1.5 about 0.1 to 0.2. Waiting until about Nov 24 to Nov 27 gives n of about 300 and 20 or more overlapping days with gold; r < 0.3 cannot be resolved before about Nov 29 even at the best case.
