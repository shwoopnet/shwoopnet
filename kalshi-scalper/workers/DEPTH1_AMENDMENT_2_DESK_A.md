## The five that matter most
(a) TIME ANCHORS. SAME as Forensics. Poll time = t_recv_ms/1000 + the run's clock offset. The decision poll S = the last poll with t <= close-480 s and t >= close-490 s (`last_at`, tolerance 1e-9). The 30 s and 60 s lookback polls = the last poll at or before S.t-30 / S.t-60 and no more than 6 s earlier. The fill = the first poll with t >= S.t+1.0 s and t <= S.t+21.0 s. Tape window: trades with S.t-60 < t <= S.t (open at the start, closed at the end). All measured from S.t, not from T-480 s. DIFFERS in the tape boundary: Forensics uses [S.t-60, S.t); V2 includes a trade exactly at S.t and excludes one exactly 60 s earlier.
(b) COVERAGE RECEIVE TIMES. DIFFERS. V2's usable() compares first_recv_ms/1000 and last_recv_ms/1000 RAW (no clock offset) with close-545 s and close-470 s, and requires first_recv_ms > 0. Forensics adds the run offset first. I changed nothing; whether the raw local clock or the offset one is meant is the Head's ruling. (The fixture run shows the gap this makes in usable windows: 1,309 mine against 1,317.)
(c) A TICKER IN TWO RUNS. SAME. Per (close, series) the coverage row with the strictly larger ok_polls wins (ties keep the first run in sorted run-path order); that run's book and tape rows are the only ones used. One window counts once.
(d) THE Z. DIFFERS. mu = mean net per trade; keys = US Central close date (fixed rule: UTC-5 before 2026-11-01 07:00 UTC, UTC-6 after); z = mu / sqrt( sum over dates of (date sum - date count x mu)^2 / n^2 ). There is NO D/(D-1) correction. Forensics multiplies the sum by D/(D-1), so its z is larger by sqrt(D/(D-1)) (about 3.5% at 15 dates). n < 2 gives 0. Variance 0 gives 0. The bar z 5.27 and the shared 5.46 are from N 728,648 (Phi^-1(1 - 0.05/728648)).
(e) THE SHUFFLE. DIFFERS in one respect that may matter. numpy 2.5.3, `np.random.default_rng(20261114)` (PCG64), one generator for the whole control. Per market, windows in the scored order (runs in sorted run-path order, within a run the coverage-dict order). For each of the 20 tries (gold f1..f10, then Bitcoin f1..f10) the sign vector (+1 buys YES, -1 buys NO, 0/None no trade) is stored with the window's own YES and NO net-pnl vectors (NaN where no fill). Each round (1,000) draws `rng.permutation(n_windows_of_that_market)` ONCE PER TRY, in that fixed order, so 20 permutations a round, drawn independently: the ten features of a window do NOT move together (each try gets its own permutation). Per try per round: the trade value of a window is the YES pnl where the shuffled sign > 0, the NO pnl where < 0, NaN dropped; mean net per trade, or -1e9 if under 30 trades. The round's best = the maximum over the 20; threshold = np.percentile(best, 99) (linear interpolation). Observed value per try = the same function on the unshuffled signs. Marginal p = (1 + number of rounds with best >= observed) / 1001. A try passes the control if observed > threshold. Draws cannot match another language's, so only a rebuild in numpy with this order reproduces the 99th percentile to the digit; the separate-vs-together choice also moves it. Not a fixed-seed fault (the seed is fixed).

A run with no readable Date header has no clock and ALL its usable windows are excluded and counted as "no clock" (granularity: the whole run, not one window); above 20% of usable windows -> NOT_RUNNABLE. Close = coverage close_time.

3. (c) above.
4. Decision poll. DIFFERS slightly. V2 takes S as any poll in [T-490, T-480] and does not require both level-1 bids; a poll with a missing side gives None features for the book ones (no trade), the window still counts as "with a decision poll". Forensics returns "no quote" and does not count it. Tape and 30/60 s features need only the other fields.
5. Lookbacks from S.t. SAME (see a).
6. Tape window. See (a).
7. Fill poll. SAME (see a). The fill needs the implied side's ask in 0.10 to 0.90 (tolerance 1e-9) and the ask size >= 1.
8. f3. SAME: weighted YES bid over the five levels, weighted YES ask = 1 - weighted NO bid, minus the plain mid (yes bid1 + 1 - no bid1)/2; needs both sides' size sums > 0.
9. f6. SAME: needs the 60 s poll and both sides at both times; thin side = the one with the smaller 5-level size then; thin NO: (n0-n1)/n0; thin YES: -(y0-y1)/y0; equal -> 0.0; a zero size then -> None.
10. f8 and f9. SAME: f8 gap = level-1 price minus level-2 price, a missing level 2 uses 0 (so gap = the level-1 price); f9 needs two levels a side and a positive size sum, slope = (px[0]-px[-1])/sum(sizes) over up to five levels.
11. f10. SAME: sizes within 0.03 of each side's own touch, tolerance 1e-9, inclusive.
12. Zero feature. DIFFERS: V2 treats only None, NaN or exactly 0 as no trade; there is no 1e-12 band.
13. Halves. SAME: that try's trades sorted by close time, first n//2 and the rest (ties keep the scored order). Blocks by Central close date; a window dated before 2026-10-30 or after 2026-11-13 is excluded.
14. Z. (d) above.
15. Shuffle. (e) above.
16. Overlap. Gold: exactly one side's ask in 0.88 to 0.97 at the last poll at or before close-360 s (within 10 s), SAME as Forensics. Bitcoin: from V2's data/fresh.sqlite (tables market(ticker, series, close_ts) and candle(ticker, end_ts, bid_c, ask_c, oi)), held iff a side's ask (YES ask, or 1 - YES bid) is in 0.05 to 0.50 at the candle ending close-180 s AND oi at that candle minus oi at the candle ending close-360 s exceeds 86,299.56; a ticker missing either candle is "unknown". ## Ruling of the Head of R&D (Nov 13, 2026, received 00:50Z; recorded here as given)
(b), (d), (e), the decision poll without a level-1 bid, and the exact-zero feature ALL STAND AS CODED; the wrapper (75844354) and V2's depth1.py do not change. Reasons: the registration is silent on each; the code was frozen and audited before any outcome was joined; none lets anything dated after the decision into a feature; where they differ from Forensics' reading they are neutral or the stricter one.
- (b) raw receive times in the coverage test: neutral, an eligibility test on the recorder's own stamps.
- (d) the z, written out in full: z = mu / sqrt( (1/n^2) x sum over US Central close dates d of ( S_d - k_d x mu )^2 ), where mu is the mean net per trade, n the trades, S_d the sum of net per trade on date d and k_d the number of trades on date d. NO D/(D-1) factor, so the wrapper's z is the smaller of the two readings (about 3.5% at 15 dates): the stricter reading against the 5.27 bar.
- (e) an independent permutation for each of the 20 tries: breaks the correlation between tries under the null, so the 99th percentile of the best try is higher than with features moving together: the stricter control. The generator (numpy default_rng, seed 20261114), the draw order (gold f1 to f10, then Bitcoin f1 to f10, 20 draws a round), 1,000 rounds, the under-30-trades rule and the percentile method (linear, 99) are now the registered procedure. Forensics reproduces it with the same numpy generator.
