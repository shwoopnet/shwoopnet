# SHADOW_LIST_V1 ranking: the computation as text (Desk A, 2026-11-16), for Forensics' independent second build

Inputs: (a) `ENGINE1_RUN2_BARLIST_NOV16.json`, the 190 rules (series, bucket, band, side rule, filter, exit, n, pf_1c, pf_2c) that passed VALIDATE in ENGINE1 run 2; (b) the archive extract and the run 2 split constants; scoring is exactly `ENGINE1_SPEC_NOV15.md` (raw ask entry, haircut h 0.01 and 0.02, fee ceil(round(0.07 x 10 x p x (1-p) x 100, 9)) per order per leg, exits as written there, cash rounded to 9 places). My own rescored table for comparison is `ENGINE1_RUN2_RESCORE_NOV16.json` (do not open it before your reader is committed).

1. **Per rule, VALIDATE.** n = scored entries at 1c (must equal the listing's n; reproduce the listing's n, pf_1c, pf_2c first, to 1e-9). net_1c, net_2c = total cash in dollars of those entries at 10 contracts at h 0.01 and 0.02. VDAYS = (last VALIDATE market close of that series, as an epoch) minus (00:00 UTC of the day after the series' last SEARCH date) divided by 86400, a real number of days. signals_per_day = n / VDAYS.
2. **Per rule, SEARCH.** sn = scored entries at 1c in the SEARCH phase for the same rule key (same bucket, band, side rule, filter with spread cuts from SEARCH, exit). SDAYS = (last SEARCH market close minus first SEARCH market close of that series) / 86400 + 1. search_signals_per_day = sn / SDAYS.
3. **Edge.** edge_c_per_contract = net / (n x 10) x 100 (cents per contract), at 1c (net_1c) and at 2c (net_2c, n the 2c count, which equals n).
4. **Income.** dollars_week_1c = signals_per_day x (net_1c / (n x 10)) x 5 x 7 = signals_per_day x edge_1c / 100 x 35; dollars_week_2c the same with net_2c.
5. **Admission.** Drop every Dogecoin rule (declined list 7e). Keep a rule only if signals_per_day >= 3 AND search_signals_per_day >= 3 (counted per rule, in that order; all 190 pass both, so nothing else is dropped).
6. **Family** of a rule: "F1 favourite-late shape" if band >= 17 and bucket <= 600; otherwise kind x region, kind = "open-interest trigger" (filter feature oi3 or oi6), "momentum or volume filter" (mom1, mom3, mom5, vol3), "spread filter" (spread), else "plain band"; region = "cheap tail" if band <= 6, "middle" if band <= 16, else "high price".
7. **Clusters.** Two rules are linked if same series, same side rule, same exit, |bucket difference| <= 60 and |band difference| <= 1; clusters are the connected components (transitive). Within a cluster sort by dollars_week_1c descending, then pf_2c descending, then bucket ascending, band ascending, str(filter) ascending; the first is the representative.
8. **Pick order.** Sort clusters by representative dollars_week_1c descending, ties by series, bucket, band, side rule, exit, str(filter) ascending. Walk the list once, top down: take the representative if its series has fewer than 3 picks AND its family has fewer than 5 picks AND fewer than 25 picks so far; otherwise skip it (it is not tried again and does not hold a slot; later clusters are still considered). The picks are numbered in the order taken.
9. **Print** per pick: rank, series, bucket, band, side rule, filter, exit, n, signals_per_day, edge_1c, edge_2c, dollars_week_1c, dollars_week_2c, family; plus the count of clusters and picks. Tolerance 1e-9 on every figure, exact on the integers and on the pick list.

A and B are within 60 s and one band of each other and share side and exit: one cluster, representative A. C is dropped before clustering.
