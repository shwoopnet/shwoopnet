# WHEEL0: what the frozen scorer does on the Verification Analyst's 11 points (Forensics desk, Nov 13, 2026)

Answered from `wheel0.py` sha256 `10a7b3630be5807a...` (line numbers are that file's) and its tables, on the Head of R&D's order of 15:33Z. The code is the definition; nothing was changed, no run was opened. Where the code has no answer, it says so.

1. **Third line (88c to 97c).** Same quote rule: `template_of` (127 to 138) applies the 4c spread limit (`SPREAD_MAX`, 25; line 130, with 1e-9) and the no-tie rule (132) to every template, and the favourite side is the side with the higher ask (134). The 88c to 97c band (`FAV_HI`, 24) is assigned only to the favourite kind and only when no ordinary favourite band holds the ask (136). Three looks (600, 360, 180 s; `LOOKS`, 21) per market as for every template; one order per market, look and side kind (171). A block is at least 150 orders (`FAV_BLOCK_MIN`, 27; `grid`, 268) and runs on to its 10th loss (`FAV_LOSSES`/`RARER_MIN`, 26 to 27; `build_blocks`, 254). HOT is the same `is_hot` (400). It is reported apart in `favourites` (395 to 406), skipped by `primary` (298), `_split` (319) and `secondary` (385), never pooled.
2. **Where a block ends.** `build_blocks` (247 to 258): start at `i`, extend `j` until the block holds at least `min_len` orders (60, or 150 for the third line) AND at least `RARER_MIN` (10) of the rarer outcome (wins for a cheap-side template, losses for a favourite-side one; 254); it ends at the FIRST `j` meeting both (255), the next block starts at `e + 1` (257). A trailing tail that never completes is NOT a block (256, and the docstring, 249). Within `is_hot` the halves are the first `len // 2` orders and the rest (243 to 244).
3. **HOT pair and D.** `primary` (294 to 312): inside each (series, template) group, every block with a predecessor is a pair (`pairs += 1`, 303); it is a HOT pair when the block BEFORE it is HOT (`hot_pairs += flags[i - 1]`, 303). Blocks of different series or templates are never paired. The verdict's count of 30 reads `hot_pairs` (350; `VERDICT_MIN_HOT`, 28). D is the mean cash per ORDER (one order of 10 contracts, in dollars) of the orders in blocks that follow a HOT block, minus the same mean for orders in blocks that follow a not-HOT block (`boot_p`, 281 to 284: `sh / nh - sn / nn`); it is not a mean of block means. Day label: the UTC date of the market's close (177).
4. **Bootstrap interval and p.** `BOOT_N` 10,000, `random.Random(20261112)` (29, 286). Each repetition draws `len(days)` UTC days with replacement (288), recomputes D, and skips a repetition in which either side has no order (283, 289), so the list `ds` can hold fewer than 10,000. It is sorted (290). Interval: `[ds[int(0.025 * len(ds))], ds[int(0.975 * len(ds)) - 1]]` (291), zero-based: with 10,000 values the 251st smallest and the 9,750th smallest. p = the share of `ds` that is at or below zero (`v <= 0`, no tolerance), over `len(ds)` (291). One-sided.
5. **Null-calibrated p.** `null_calibration` (326 to 346): 500 repetitions (`NULL_REPS`, 43), `random.Random(SEED + 1)` (336); every repetition draws one result per market, in sorted ticker order, `rng.random() < fair[t]` (336, 338), where `fair` is the market's YES mid at its latest two-sided look (looks tried 180, then 360, then 600; `fair_yes`, 181 to 189); orders and prices are kept, win and loss cash are recomputed (339), blocks are rebuilt with `build_blocks(..., BLOCK)` for every ordinary template (320) and D computed only if both sides have orders (341). p = `(1 + number of repetitions with D at or above observed D minus EPS) / (repetitions + 1)`, EPS 1e-9 (30), rounded to 4 decimals (344). The verdict reads that rounded figure with `<= 0.05 + EPS` (353).
6. **A void.** `cash` (146 to 151): no yes or no result gives `-fee`, win is None. `report` (423 to 425) counts the voids and then sets `win = False`: a void is a fee-only loss in profit factor (233 to 235) and counts as a loss. In a block's rarer-outcome count (254) it therefore counts as a loss (so it counts toward the 10 losses of a favourite-side block) and is not a win (so it does not count toward the 10 wins of a cheap-side block). Note for anyone comparing with the lane's own "void is neither win nor loss" wording: in this code a void IS counted as a loss for the favourite-side count. The null calibration draws yes or no only, so it has no voids.
7. **Rule (h) and the lower bound.** `read_markets` (70 to 85), on the close time (`_iso`, 80): a market with no readable close is dropped (81); `FROM <= close < BEFORE` (82) with `FROM` 2026-09-12T00:00:00Z inclusive and `BEFORE` 2026-11-13T00:00:00Z exclusive (32); then Bitcoin or Ethereum with close at or after 2026-10-29T00:00:00Z is dropped and counted (`RULE_H_BEFORE`, 35; line 83). All of it before candles load: `read_candles` keeps only wanted tickers (100, 108). Book mode takes gold, XRP and Dogecoin only (`BOOK_SERIES`, 36; assert, 195). The scorer's own guard is the `HELDOUT_` folder name (51 to 54); it does not read `HELDOUT_PULL_RUNS.md` (that is the pre-run check).
8. **Candle price units.** `_px` (88 to 96): `close_dollars` first, else `close`; strings read as floats; a `close` value above 1.0 is read as cents and divided by 100 (95). Prices are dollars. Only the close of the yes_bid and yes_ask objects is used, from the candle whose `end_period_ts` equals the market's close minus the look exactly (167); a later answer overwrites an earlier one for the same end time (111).
9. **Per-market null.** The code has none. `null_calibration` runs once, on the pooled orders (427 to 428). `primary_by_market` (432) calls `primary(g, s)` per series (bootstrap only) and labels it `verdict(primary(g, s))` with no null p, which can never reach SUPPORTED because the rule needs both p values (`VERDICT_NEEDS_BOTH_P`, 37; 353), only NOT SUPPORTED or "no evidence"; the line says it is descriptive.
10. **A "within 0.001 of a bar" print.** None. The code prints no near-bar flag; the rule of the 00:18Z dated line is procedural (both builds recompute in exact whole cents). The verdict (349 to 356) compares the figures as printed: profit factor rounded to 3 decimals (309), D and both p values to 4 (311, 344), then `>= bar - EPS` (354); the one raw comparison is `pfh < 1.0` (355) and `d <= 0`.
11. **Fee on the rounded ask.** Yes. `template_of` decides the band and the tie on the exact ask (`in_band`, 122 to 124 with 1e-9; tie test, 132; side choice, 134) and returns `round(ask, 4)` (137). The order, the cash result and the fee all use that rounded price (`orders_from_candles`, 176 to 177; `cash`/`fee10`, 141 to 151); book mode uses `round(cost / SIZE, 4)` (227). Fee = `ceil(0.07 * p * (1 - p) * 10 * 100 - 1e-9) / 100` for one order of 10 contracts (143). On whole-cent quotes the rounding changes nothing.
